# 章节大纲输出模板

本文件提供 A 类（新章）和 B 类（补全）两种大纲的完整格式模板，从 Analyse Complexe Ch2-9 的实际规划中提炼。

---

## A 类模板（新章规划）

```markdown
# 第X章「Title // 中文标题」写作大纲

## 零、章节定位与核心洞察

**章节定位**：一句话说明本章在全书中的角色（承接什么、开创什么）。

> 例：本章是 Cauchy 积分公式的应用章，将 CIF 从"积分公式"升级为"函数性质判据"，
> 为后续级数展开和留数计算提供分析工具。

**核心洞察**：全章的灵魂命题，一句话概括本章要传递的数学思想。

> 例：解析函数的局部性质（模的最大值、导数的估计、零点的分布）全部可以从
> CIF 的积分表示统一推出——"积分公式 ⇒ 函数刚性"。

**预估规模**：~XXX 行新增内容，Y 节，Z 个新标签，W 张图

## 一、结构方案

| 节 | 标题 | 预估行数 | 现状与调整 |
|---|---|---|---|
| §X.1 | Title // 中文 | ~NN | 引言 prose 保留；补 label + 证明 |
| §X.2 | Title // 中文 | ~NN | ★新增节（说明理由） |
| §X.3 | Title // 中文 | ~NN | 现有 prose 组件化 |

组织主线：说明节序安排的逻辑（常用："理论 → 方法/例题 → 分类/应用"三段递进）。

## 二、组件频率预估

| 组件类型 | 数量 | 标签清单 |
|---------|------|---------|
| `#definition` | N | `<def:xxx>`, `<def:yyy>` |
| `#theorem` | N | `<thm:xxx>` |
| `#proposition` | N | `<prop:xxx>` |
| `#corollary` | N | `<cor:xxx>` |
| `#lemma` | N | `<lem:xxx>` |
| `#example` | N | `<ex:xxx>` |
| `#property` | N | `<prop:xxx>` |
| `#note` | N | （无标签） |
| `#figure` | N | `<fig:xxx>` |

## 三、各节知识点、组件与标签

### §X.1 Title // 中文

| 内容 | 组件/标签 | 备注 |
|---|---|---|
| 核心概念定义 | `#definition` `<def:xxx>` | 回链 `@label`（说明从哪里引入） |
| 关键定理 | `#theorem` `<thm:xxx>` | 证明策略：用 CIF + 引理 YYY |
| 推论 | `#corollary` `<cor:xxx>` | 由 `@thm:xxx` 直接得 |
| 引理 | `#lemma` `<lem:xxx>` | 定理证明的心脏；独立成引理便于复用 |
| 例题 | `#example` `<ex:xxx>` | 回链 `@def:xxx` |
| 注记 | `#note` | 无编号；呼应引言 / 预告后续 |

### §X.2 Title // 中文
（同上格式）

|------|------|------|------|

## 六、证明策略表

对每个需要完整证明的定理，预先规划证明路线：

| 定理 | 证明策略 | 关键工具 |
|------|---------|---------|
| `<thm:xxx>` | CIF + 核展开引理 → 逐项积分 | `@lem:geometric-kernel`, `@thm:cif` |

## 七、公式编号规划

基于依赖分析，建议写入顺序：

1. §X.1（基础定义 + 引理）→ 编译验证
2. §X.2（核心定理，依赖 §X.1 引理）→ 编译验证
3. §X.3（应用/例题）→ 编译验证
```

## 模板使用说明

### 章节定位与核心洞察

- **章节定位**回答"这一章在全书中做什么"——承上启下的角色
- **核心洞察**是全章的灵魂命题，一句话概括本章要传递的数学思想
- 二者帮助在规划阶段确认本章的 SRP 边界，避免与前后章节职责重叠

### 组件频率预估

- 在规划阶段估算每类组件的数量，防止某类组件过多或过少
- 帮助评估工作量（标签数 ≈ 写作量）
- 实际写入时允许微调，但偏差超过 30% 应回头审视结构

### 承诺追踪

- **兑现**：前章某处写了"将在 §X.Y 证明"，本章必须兑现该承诺
- **埋下**：本章某处写了"将在 ChW 证明"，记录为未来任务
- 用行号（如 L536）精确定位承诺位置，便于检索

### 证明策略表

- 对每个需要完整证明的定理，**在规划阶段**就确定证明路线
- 列出关键工具（哪些引理/定理/定义会被引用）
- 避免写作时才发现证明需要的前置知识尚未建立

### 写作顺序建议

- 基于依赖分析而非章节编号顺序
- 引理先于定理、定义先于例题
- 每写完一节即编译验证（分批编译策略）
