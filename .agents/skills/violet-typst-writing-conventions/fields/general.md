# 通用符号与硬规则（general.md）

本文件是**一切数学笔记的基座**，写任何 `.typ` 公式前始终加载。通用硬规则指"任何数学笔记都会出现的错误"，不分学科。

路由约定：关系/箭头/集合逻辑/微积分/线性代数等家族符号见 [README.md](README.md) 的符号路由表，分别加载对应文件。

## 1. 数学模式基本用法

- 行内公式：`$ ... $`（与文本同行）
- 行间公式（display math）：`$ ... $`（单独成段，前后有空行或换行）
- **导数记号随模式区分**：行内一律用下标形式（`u_t`），行间一律用分式形式（`(partial u)/(partial t)`），详见 [calculus.md §9](calculus.md)（2026-10-19 用户定稿）

## 2. 硬规则（必须遵守）

1. **不属于符号**：写 `$in.not$`，不要写 `$notin$`（`notin` 不存在）
2. **子集**：统一写 `$subset$`（详见 relations.md）
3. **箭头**：`$->$`、`$<=>$`，不保留 LaTeX 宏名（详见 arrows.md）
4. **不等于**：`$!=$`（注意空格：`$!= $` 或 `$a != b$`，详见 relations.md）
5. **函数复合**：`$compose$`
6. **微分符号**：使用正体 `dif x`、`dif t`（详见 calculus.md）
7. **导数点记号**：`dot(x)`、`dot.double(x)`、`dot.triple(x)`（详见 calculus.md）
8. **积分号**：用 `integral`，不是 `int`。二重/三重：`integral.double`、`integral.triple`（详见 calculus.md）
9. **`text()` 必须用字符串参数**：写 `text("something")`，不是 `text(something)`
10. **点乘**：写 `a dot b`，不用 `a cdot b`（`cdot` 不存在）
11. **下标后紧接括号，下标必须用 `{}` 包裹**，否则括号会被吞进下标：写 `mu_(X)(B)`，**绝对禁止** `mu_X(B)`（这是全仓库最高频、AI 最易再犯的 Typst 语法错误，见下方专门小节）
12. **`\left(`/`\right)` 不存在**：Typst 自动缩放括号，不需要 `\left`/`\right`

## 3. 下标（最高优先级）

### 3.1 裸下标问题

Typst 不支持 `$_x$`，下标 `_` 前必须有主体。

```typst
// 错误
$_x$

// 正确：空主体下标
$""_x$
```

### 3.2 ⚠️⚠️⚠️ 绝对禁止：下标后紧接括号必须用 `{}` 包裹下标（三维基准） ⚠️⚠️⚠️

> 🔴🔴🔴 **这是全仓库最高频、AI 反复再犯、被用户在 Review 中当场抓出的错误。每次写完任何带下标 + 括号的数学公式，必须立刻用正则 `_([a-zA-Z])\(` 自查，不做这一步禁止提交。** 🔴🔴🔴

**任何"下标是一个符号、后面紧跟一个括号作为函数参数"的写法，都必须把下标用 `{}` 裹起来**，否则 Typst 会把整个 `下标+括号+括号内容` 全部归入下标，渲染成叠成小字的错误结果。

### 3.3 单字母下标后接括号（`GL_n(F)` 问题）

**单字母下标后直接跟一个括号时，括号及其中内容会被 Typst 一并归入下标**，而不是作为括号表达式紧跟在右侧：

```typst
// 错误 — 整个 "n(F)" 都被当作下标，渲染成 G L 的下标下标小字
$"GL"_n(F)$      // 实际渲染：GL_{n(F)}，且 F 被错误地放进下标
$f_n(A)$         // f_{n(A)}，括号 (A) 被吞进下标
$mu_P(x, y)$     // mu_{P(x,y)}
$mu_X(B)$        // mu_{X(B)} —— 本次 Probabilités 实际踩中的坑！
$"Syl"_p(G)$     // Syl_{p(G)}
$C_G(H)$         // C_{G(H)}

// 正确 — 括号作为独立的函数参数贴在右侧
$"GL"_(n)(F)$    // GL_n (F) —— n 是下标，(F) 是独立的参数
$f_(n)(A)$       // f_n (A)
$mu_(P)(x, y)$   // mu_P (x, y)
$mu_(X)(B)$      // mu_X (B) —— X 是下标，(B) 是独立参数
$"Syl"_(p)(G)$   // Syl_p (G)
$C_(G)(H)$       // C_G (H)
```

**判定规则**：只要遇到形如 `_<单个字母>` 且后面紧跟 `(` 的模式（`"GL"_n(F)`、`f_n(A)`、`C_G(H)`、`mu_P(x,y)`、`"Syl"_p(G)`、`N_G(H)`、`phi_g(x)` 等），一律改写为 `_<字母>(` + `)(` 形式，即 `"GL"_(n)(F)`。批量替换时注意两点：

- 括号里的多字母（如 `"GL"_(n)(F)`）用 `{...}` 包裹下标；**真正作为函数参数的括号要写在 `)` 之后**，不与下标粘连；
- 若下标本身是普通变量而非"名字 + 参数"，如 $x_i^2$ 或 $n_k$，则无需改动——只处理**下标后紧跟 `(`** 的情形（此时 `(` 是想作为独立参数而非下标）。

**批量排查**：在全仓库 `.typ` 文件中搜索正则 `_([a-zA-Z])\(`，逐个改为 `_($1)(`。这与你之前修的 `f_n(A)` 是同一种错误，务必全局替换，不限于举例处。

## 4. 多字母变量问题

Typst 将连续字母识别为内置函数名（如 `sin`、`exp`），或把相邻的单字母变量合并为一个未知多字母变量，导致编译错误。

```typst
// 正体多字母变量：用引号包裹
$"ext"$, $"const"$, $"max"$

// 斜体多字母变量：用空格分开
$e x t$

// 示例
$bold(F)_i^("ext")$  // 外力
```

**相邻单字母变量之间必须用空格分隔**，否则整体被识别为一个未知变量（报 `unknown variable: xy` 等）：

```typst
// 错误 — 字母连写被合并为单个未知变量
$xy$     // → unknown variable: xy
$2xy$    // → unknown variable: xy
$2 x y z$ 若写成 $2xyz$

// 正确 — 变量与变量之间留空格
$x y$
$2 x y$
```

数字紧跟单个变量（如 `$2x$`）本身合法，但建议统一写成 `$2 x$` 保持风格一致。

**排查指南**：遇到 `unknown variable` 错误时，优先排查两类根因——多字母连写（如 `xy`、`2xy`）与 LaTeX 宏残留（如 `cdot`、`int`、`infty`）。

## 5. 字体命令

### 5.1 数学字体

| LaTeX | Typst |
|-------|-------|
| `\mathbb{R}` | `bb(R)` |
| `\mathcal{F}` | `cal(F)` |
| `\mathscr{M}` | `scr(M)` |
| `\mathfrak{g}` | `frak(g)` |
| `\mathrm{d}x` | `dif x` |
| `\mathrm{Re}` | `Re` |

### 5.2 组件参数中的引号嵌套

组件的 `name:` / `title:` 等字符串参数内部**不能直接嵌套双引号**，否则字符串提前终止，报 `unclosed delimiter` / `expected comma`：

```typst
// 错误 — 内层双引号截断了外层字符串
#note(title: "On the Usage of "Holomorphic" and "Analytic")[...]

// 正确 — 内层改用单引号
#note(title: "On the Usage of 'Holomorphic' and 'Analytic'")[...]
```

### 5.3 组件 name/title 参数中的数学公式

`name:` / `title:` 参数可以传字符串（`"..."`）或 content（`[...]`），两种形式都能正确渲染其中的 `$...$` 数学公式。模板已通过 `eval(name, mode: "markup")` 自动解析字符串中的 markup 语法。

```typst
// 两种写法都正确，数学正常渲染
#definition(name: "$L^p$ Space")[...]
#definition(name: [$L^p$ Space])[...]

// 推荐：字符串形式更简洁
#theorem(name: "Properties of $sin$ and $cos$")[...]
```

**注意**：使用字符串形式时，`$...$` 内的 Typst 数学符号必须正确（如 `!=` 而非 `neq`），否则 `eval` 解析时会报 `unknown variable` 错误。

### 5.4 `text()` 字符串参数

Typst 的 `text()` 函数必须传入字符串，未加引号的参数会被当作变量：

```typst
// 错误 — "self" 被当作变量名
$U_(text(self))$

// 正确
$U_(text("self"))$
```

## 6. 分数与非单因子括号

### 6.1 分数的分子/分母非单因子时必须加括号

`/` 只把紧邻的**单个因子**作为分子和分母。分母（或分子）含多字符结构或运算时必须加括号，否则解析错误。

**绝对值的特殊处理**：使用 `abs()` 函数形式后无需再加外层括号（`abs()` 自身作为一个完整因子）。但若使用 `|...|` 形式则必须加外层括号（见 §7）：

```typst
// 错误 — 分母只解析出单个因子，多字符结构被截断
$z^5 / |z|^4$      // 分母只取到 "|"，剩余 "z|^4" 并排在分数旁
$x + y / 2$         // 实际是 x 加上分数 y/2

// 正确 — abs() 形式（推荐，无需额外括号）
$z^5 / abs(z)^4$
$z / abs(z)$
$x / abs(z)$
$abs(f(z)) / abs(g(z))$

// 正确 — 普通非单因子加括号
$(x + y) / 2$       // 想要 (x+y)/2 必须加括号
$z^5 / (w^4)$       // 含运算的幂次也加括号保险
```

**判定规则**：分子/分母只要不是单个字母或数字（可带简单上下标，如 `x_i`、`z^2`），就必须加括号。**但 `abs(...)` 作为一个整体函数调用，可以视为单个因子**——这就是统一使用 `abs()` 形式的另一优势。

**括号组带下标 / 内层含 `/` 的整体必须再套一层括号**：分子或分母是"带下标的括号组"（如 `(...)_V`）或本身含 `/`（如偏导 `partial U / partial T`）时，仅一层结构会被 Typst 拆坏（下标脱离或内层 `/` 抢占分数结构），必须整体再套一层括号：

```typst
// 错误 — 分子 (partial Q)_V 未整体包裹；偏导整体含裸露的 /
$(partial Q)_V / (dif T)$
$C_V = (partial U / partial T)_V$

// 正确 — 多字母分子/分母各自整体加括号，偏导先组内配对再挂下标
$C_(V, m) = ((partial Q)_V) / (nu dif T) = 1 / nu ((partial U)/(partial T))_V$
```

## 7. 绝对值用 abs(xxx)，不用 |xxx|

Typst 数学模式中的 `|...|` **不会自动调整大小**，且在分式、根号、嵌套结构中容易被解析为独立竖线元素。**统一使用函数形式 `abs(xxx)`**，自动缩放并避免歧义：

```typst
// 错误 — |xxx| 不会自动缩放，且容易被误解为单字符
$|z - z_0|$
$|f(z)| / |g(z)|$
$root(n, |a_n|)$

// 正确 — abs() 自动缩放，且作为整体单元参与解析
$abs(z - z_0)$
$abs(f(z)) / abs(g(z))$
$root(n, abs(a_n))$
```

**判定规则**：所有形如 `|表达式|` 的绝对值（含 `|z|`、`|c_n|`、`|z - z_0|`、`|f(z)|` 等）一律改写为 `abs(表达式)`，不论出现在正文公式、分式分子分母、根号内、积分限、求和限等任何位置。

**非绝对值的竖线严禁转换**：`|` 在数学模式中还有其他用途，批量替换前必须逐行分类排查（统计每行 `|` 个数，奇数行必然含非绝对值竖线）：

| 用途 | 示例 | 处理 |
|------|------|------|
| 集合构建分隔符 | `{(x, y) \| x, y in bb(R)}` | 保留原样（本仓库写法为 `\|`） |
| 整除符号 | `$q \| k_1 - k_2$`（q 整除 k₁−k₂） | 保留原样 |
| 分隔符参数 | `delim: "\|"` | 保留原样 |
| **行列式** | `"det"(A)` 或 `mat(delim: "\|", ...)` | 见 linear-algebra.md，**禁止 `abs()`** |

**批量替换流程要求**：先全量统计含 `|` 的行并按奇偶分类 → 偶数行逐行配对转换（行内配对，禁止跨行正则）→ 奇数行逐行人工判定 → 转换后 grep 检查 `abs(` 内是否误含 ` in `、`\|` 等集合构建特征 → `typst compile` 验证退出码为 0。跨行正则（如 `\|([^|]+)\|` 直接作用于全文）会把不同行的孤立竖线错误配对，造成大面积损坏。

**积分/求和限中的集合描述例外**：形如 `integral_({|f| > M})` 的集合描述中的 `|f|` 表示集合定义中的属性条件，作为花括号集合构造语法的一部分，**保持原样不改**——这是集合描述的语法元素，不是绝对值表达式：

```typst
// 保持原样 — 花括号内的集合描述语法
$integral_({|f| > M}) |f| dif mu$  // 集合 {|f| > M} 内的积分

// 但若此处出现了真正的绝对值计算且需要自动缩放，仍应改用 abs()
$abs(f)$
```

> **注意**：`abs()` 只用于真正的绝对值（标量、复数模、内积模）。**行列式绝不能用 `abs()`**，见 linear-algebra.md §2；范数用 `||...||`，见 linear-algebra.md §3。

## 8. n 次方根用 root(n, x)，不用 sqrt 二参形式

`sqrt(x, n)` 的第二参数（根指数）不能是函数调用或含绝对值的表达式（如 `abs(a_n)`），会报 `unexpected argument`。统一改用 `root(指数, 被开方数)`：

```typst
// 错误 — sqrt 第二参数不接受函数调用
$sqrt(n, abs(a_n))$

// 正确 — root(指数, 被开方数)
$root(n, abs(a_n))$
$root(n, n)$  // n 次根号 n
```

## 9. 常用运算符（跨学科高频，一符号一居所）

| 意图 | LaTeX | Typst |
|------|-------|-------|
| 点乘 / 内积占位 | `\cdot` | `a dot b`；占位用 `·` |
| 叉乘 / 数乘直积 | `\times` | `times`（`×` → `times`） |
| 函数复合 | `\circ` | `compose`（`∘`） |
| 正负号 | `\pm` | Unicode `±`（不用 `plus.minus`） |
| 减正号 | `\mp` | Unicode `∓`（不用 `minus.plus`） |
| 长竖线（自动缩放） | `\left\|` | `lr(\|...\|)` |

```typst
// 示例
$V times W$       // 不要写 $V × W$
$f ∘ g$           // 复合，或用 compose
$±1$              // ± 直接用 Unicode 字符
$F_y, F_z$        // 逗号下标
```

**`sim`/`cdot` 等 LaTeX 宏不存在**：Typst 数学模式不识别 `\sim`、`\cdot` 等 LaTeX 宏名。使用原生操作符：

| 意图 | 错误写法 | 正确写法 |
|------|---------|---------|
| 约等于/相似 | `$a sim b$` | `$a ~ b$` 或 `$a approx b$`（见 relations.md） |
| 点乘 | `$a cdot b$` | `$a dot b$` |
| 趋向 | `$x to oo$` | `$x arrow oo$` 或 `$x -> oo$`（见 arrows.md） |

**占位符场景**同样报 `unknown variable: cdot`：

```typst
// 错误 — cdot 作为绝对值/范数中间的占位符也是未知变量
$abs(cdot)$

// 可行 — 用 dot 充当占位符
$abs(dot)$

// 更推荐 — 在正文中改用自然语言描述（如 "the complex modulus"），避免占位符
```

## 10. 标点位置

**分两种情况，不要互相串用**（2026-10-29 用户确认口径）：独立 math 块的标点写在块内，行内 math 的标点照常写在块外。

### 10.1 独立 math 块：标点写在块内

"独立 math 块"指独占一行的 display 公式——`$` 单独成行的块，以及 `#eq[...]` 编号公式块。句末标点必须写在数学环境内部：

```typst
// 错误
$
  G(a_n; x) = sum_(n=0)^oo a_n x^n
$.

// 正确
$
  G(a_n; x) = sum_(n=0)^oo a_n x^n.
$
```

`#eq[...]` 块同理——标点要在 `$` 之内，不能落在 `$` 与 `]` 之间：

```typst
// 错误
#eq[
  $a = b q + r, quad 0 <= r < b$.
] <eq:division-identity>

// 正确
#eq[
  $a = b q + r, quad 0 <= r < b.$
] <eq:division-identity>
```

`cases(...)` 之类的块，句末标点写在 `cases(...)` 之后、闭合 `$` 之前，即 `).$`。

### 10.2 句中块不加标点

若闭合 `$` 之后的文字继续同一句（display 只作句子成分），块内不加句末标点：

```typst
// 正确：display 作 "the congruence ... has a solution" 的主语
$
  a x equiv b quad ("mod" m)
:$
has a solution if and only if ...

// 也正确：#eq 块作句中成分时，块内保留逗号，句子由后文收束
#eq[
  $a equiv b quad ("mod" m),$
] <eq:congruence-def>
if $m$ divides the difference $a - b$.
```

### 10.3 行内 math：标点照常写在公式外

行内公式不适用本条规则，标点就是普通行文标点，写在 `$` **外面**：

```typst
// 正确
... the remainder lies in $[0, b)$.
Every unit has order dividing $phi(m)$.

// 错误：把句号塞进行内公式
... the remainder lies in $[0, b.)$
```

所以"公式后面紧跟句号"本身**不是**问题：先判断它是独立块还是行内公式，只有独立块的句末标点需要内移。用 `rg '\$\.'` 之类扫描会把大量合法的行内句号误报为违规，**不得据此批量修改**；自查时只检查 `#eq[...]` 块的内容行与 `$` 独占行块的末行。

### 10.4 Display math 保持原样

如果原内容是 display math，不要擅自改写成行内数学。

### 括号自动缩放

Typst 自动缩放普通括号，通常不需要 LaTeX 的 `\left`/`\right`。需要长竖线时使用 `lr(...)`。

## 11. `cases()` 用 `quad &` 对齐，裸逗号是分行符

Typst 的 `cases()` 函数中，**裸逗号是分行符**（等价于换行）；值与条件之间用 `quad &` 对齐（留空一段距离并对齐）。**行内禁止出现渲染逗号**——` comma`、`\,`、`","` 都不得用作行内标点（2026-10-11 用户定稿，全库 40 处已按此迁移）。

```typst
// 错误 — 行内逗号是分行符，会把值和条件拆成两行
$
  cases(
    Delta u = 0, & text("in ") Omega,
    u = g, & text("on ") partial Omega,
  )
$

// 正确 — 每个条件独占一行，quad & 对齐，行末裸逗号分行
$
  cases(
    Delta u = 0 quad & text("in ") Omega,
    u = g quad & text("on ") partial Omega,
  )
$

// 同一行的两个条件用文字 "and" 连接，不用逗号
$
  cases(
    theta = arctan(y / x) quad & x != 0 "and" theta in [0, 2pi],
  )
$
```

括号内的逗号（如 `(x, y)`、`[0, 1)`、`p, q`）会被括号分组，安全、不需转义、不会分行。

常见需要查阅的情况：

- `\laplacian` 等非标准 LaTeX 宏 — Typst 不支持，需用等价表达（如 `nabla^2`，见 calculus.md）
- `\ll`、`\gg`、`\lll` 等罕见比较符号 — 可用 `<<`、`>>`、`<<<` 替代（见 relations.md）
- `\hbar`、`\ell` 等物理/数学特殊符号 — 查阅官网确认可用名称

## 13. LaTeX 宏残留扫描（每次编辑后必做）

迁移或编辑后，用以下正则扫描残留 LaTeX 宏，命中即为错误：

- `\$\` （反斜杠在数学模式中不是转义符，会渲染为字面 `\`）
- `\bmod`、`\pmod`、`\mod` → 分别用 `bmod`、`pmod`、`mod`
- `\pm` → Unicode `±`（不是 `plus.minus`，Typst 数学模式直接接受 `±` 字符）
- `\cdot` → `dot`；`\times` → `times`；`\circ` → `compose`
- `\int` → `integral`（见 calculus.md）

**排查 `unknown variable`**：优先查多字母连写（`xy`）与 LaTeX 宏残留（`cdot`、`int`、`infty`）。

## 14. Unicode 数学符号转换（通用部分）

Typst 数学模式中，部分 Unicode 符号**必须**转换为 Typst 函数名，部分**可以**直接使用。

**必须转换**（通用运算符）：

| Unicode | Typst 函数 | 正确示例 | 错误示例 |
|---------|-----------|----------|----------|
| `×` | `times` | $V times V$ | $V × V$ |

**可以直接使用**（通用，Typst 数学模式原生支持，渲染正确）：

| Unicode | 含义 | 示例 |
|---------|------|------|
| `±` | 正负号 | $±1$ |
| `∓` | 负正号 | $a ∓ b$ |
| `·` | 点乘占位符/内积占位 | $(·, ·)$ |
| `∘` | 复合 | $f ∘ g$ |
| `⊥` | 正交/正交补 | $W^⊥$、$alpha ⊥ beta$（见 linear-algebra.md） |
| `†` | 伴随矩阵/共轭转置 | $A^†$（见 linear-algebra.md） |
| `≈` | 同构/等价 | $V ≈ V'$（见 relations.md） |
| `⊕` | 直和 | $V_1 ⊕ V_2$（见 linear-algebra.md） |
| `∂` | 偏导 | $partial f / partial x$（见 calculus.md） |
| `↝` | 映射箭头 | $alpha ↝ beta$（见 arrows.md） |

集合/逻辑/关系类 Unicode（`∩ ∪ ∀ ⊂ ⊃ ⊆ ≠ ≤ ≥`）见 relations.md 与 sets-logic.md 的对应表。
